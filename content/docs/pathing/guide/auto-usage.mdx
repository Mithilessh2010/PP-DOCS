We now have everything needed to build an autonomous: a follower, Poses, paths, and a way to follow them.

If you need to revisit a step, see [Creating a Follower](/docs/pathing/guide/follower-creation), [Creating a Pose](/docs/pathing/guide/pose-creation), [Creating a Path](/docs/pathing/guide/path-creation), or [Following a Path](/docs/pathing/guide/path-following).

We'll look at how to build an autonomous both without Ivy and with Ivy.

## Without Ivy

For a larger autonomous, create the Poses the robot needs to visit:

```java
private final PoseFactory p = PoseFactory.degrees();

private final Pose startPose = p.of(24, 24, 0);
private final Pose scorePose = p.of(48, 48, 90);
private final Pose parkPose = p.of(72, 48, 90);
```

Then create fields for the paths:

```java
private Path scorePath;
private Path parkPath;
```

### Creating the Paths

Create the paths inside `start()` and begin following the first one:

```java
@Override
public void start() {
    scorePath = line(startPose, scorePose)
            .linear(startPose, scorePose);

    parkPath = line(scorePose, parkPose)
            .linear(scorePose, parkPose);

    follower.follow(scorePath);
}
```

### Moving Between Paths

Without Ivy, one way to move through an autonomous is to keep track of the current step.

Create a state:

```java
private int pathState = 0;
```

Then check when the follower finishes:

```java
@Override
public void loop() {
    follower.update();

    if (!follower.isBusy() && pathState == 0) {
        // Run mechanism code here.

        follower.follow(parkPath);
        pathState = 1;
    }
}
```

When `scorePath` finishes, the robot begins `parkPath`.

More states can be added as the autonomous gets larger.

### Complete Example

```java title="ExampleAuto.java"
package org.firstinspires.ftc.teamcode;

import static com.pedropathing.api.Paths.*;

import com.pedropathing.api.PoseFactory;
import com.pedropathing.follower.Follower;
import com.pedropathing.math.Pose;
import com.pedropathing.paths.Path;
import com.qualcomm.robotcore.eventloop.opmode.Autonomous;
import com.qualcomm.robotcore.eventloop.opmode.OpMode;

import org.firstinspires.ftc.teamcode.pedroPathing.Constants;

@Autonomous(name = "Example Auto")
public class ExampleAuto extends OpMode {

    private Follower follower;

    private final PoseFactory p = PoseFactory.degrees();

    private final Pose startPose = p.of(24, 24, 0);
    private final Pose scorePose = p.of(48, 48, 90);
    private final Pose parkPose = p.of(72, 48, 90);

    private Path scorePath;
    private Path parkPath;

    private int pathState = 0;

    @Override
    public void init() {
        follower = Constants.create(hardwareMap);
        follower.setPose(startPose);
    }

    @Override
    public void start() {
        scorePath = line(startPose, scorePose)
                .linear(startPose, scorePose);

        parkPath = line(scorePose, parkPose)
                .linear(scorePose, parkPose);

        follower.follow(scorePath);
    }

    @Override
    public void loop() {
        follower.update();

        if (!follower.isBusy() && pathState == 0) {
            // Run mechanism code here.

            follower.follow(parkPath);
            pathState = 1;
        }

        telemetry.addData("Pose", follower.pose());
        telemetry.addData("Path State", pathState);
        telemetry.update();
    }
}
```

## With Ivy

[Ivy](/docs/ivy) lets us organize the same autonomous as commands instead of manually keeping track of states.

Add the Ivy imports:

```java
import com.pedropathing.ivy.Command;
import com.pedropathing.ivy.Scheduler;

import static com.pedropathing.ivy.Scheduler.schedule;
import static com.pedropathing.ivy.groups.Groups.sequential;
import static com.pedropathing.ivy.pedro.PedroCommands.follow;
```

### Creating the Routine

`sequential()` runs each command one after another:

```java
private Command autoRoutine() {
    return sequential(
            follow(
                    follower,
                    line(startPose, scorePose)
                            .linear(startPose, scorePose)
            ),

            // Add mechanism commands here.

            follow(
                    follower,
                    line(scorePose, parkPose)
                            .linear(scorePose, parkPose)
            )
    );
}
```

The second path begins after the first `follow()` command finishes.

Other Ivy commands can be placed between the paths or run alongside them using different command groups.

### Running the Routine

Reset Ivy and create the follower inside `init()`:

```java
@Override
public void init() {
    Scheduler.reset();

    follower = Constants.create(hardwareMap);
    follower.setPose(startPose);
    follower.update();
}
```

Schedule the routine inside `start()`:

```java
@Override
public void start() {
    schedule(autoRoutine());
}
```

Then update both systems inside `loop()`:

```java
@Override
public void loop() {
    follower.update();
    Scheduler.execute();
}
```

<Callout title="Tip" type="info">
    See the [Ivy documentation](/docs/ivy) to learn about commands, sequential groups, parallel groups, and other ways to organize an autonomous.
</Callout>

Both approaches use the same follower, Poses, and paths. Ivy changes how the different actions in the autonomous are organized.
